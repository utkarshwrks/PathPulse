# Replay logs

JSONL, one `SensorSample` per line — exactly what the engine saw, verbatim.

| Prefix | What it is |
| --- | --- |
| `sim_*` | **Simulated.** Generated by `pnpm eval:record` from the physics model. Deterministic and committed, so `docs/benchmarks.md` reproduces from this repository alone. |
| `drive_*` | **Real.** Recorded on a phone from an actual drive or walk. None exist yet. |

The eval harness treats both identically — that is the point of having a format
rather than a special case. But `docs/benchmarks.md` states at the top when
every log is simulated, because presenting a simulated figure as a road result
would be the most damaging thing this project could do.

## Recording a real one

Drive or walk a route with **good** GNSS for five to ten minutes with the app
recording, then use **Download recording (.jsonl)** and drop the file here as
`drive_<place>_<n>.jsonl`.

Good GNSS throughout is the requirement, not a nicety: the recorded fixes become
the ground truth that the artificial outage is scored against. A log recorded in
an urban canyon measures the estimator against a bad reference and tells you
nothing.

```bash
pnpm eval -- --list
pnpm eval -- --log drive_jabalpur_01.jsonl --config full
pnpm ablation
```
