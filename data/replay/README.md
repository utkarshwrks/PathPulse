# Replay logs

JSONL, one `SensorSample` per line — exactly what the engine saw, verbatim.

| Prefix | Tier | What it is |
| --- | --- | --- |
| `sim_*` | **S** | **Simulated.** Generated by `pnpm eval:record` from the physics model. Deterministic and committed, so `docs/benchmarks.md` reproduces from this repository alone. |
| `iovnbd_*` | **R** | **Real sensors, not our device.** Converted from the IO-VNBD dataset by `pnpm data:iovnbd`. Real smartphone IMU in a real car with the vehicle's own CAN bus as a cross-check. |
| `drive_*` | **F** | **Field.** Recorded on our phone, on our roads. None exist yet. |

## What each tier can and cannot prove

|  | Tier S `sim_*` | Tier R `iovnbd_*` | Tier F `drive_*` |
|---|---|---|---|
| Real IMU vibration | ✗ | ✓ | ✓ |
| Real GPS on a real road network | ✗ | ✓ | ✓ |
| Real turn geometry | ✗ | ✓ | ✓ |
| Our phone, our mount | ✗ | ✗ | ✓ |
| Our roads, our region | ✗ | ✗ | ✓ |
| Barometer, NavIC, C/N0 spread | ✗ | ✗ | ✓ |
| 50–100 Hz sampling | ✓ | ✗ (10 Hz) | ✓ |

**Never average tiers into one number.** A Tier R result is strong evidence that
something works on real sensors and is *not* evidence that it works on our
handset — say both, in the same sentence, every time.

### Why Tier R exists

Tier S flatters the estimator badly, and now there is a number for how badly:
the shipped configuration measures **6.9 % mean drift on Tier S and 41.3 % on
Tier R** — and the Tier R figure is already after fixing a speed runaway that
only real sensors exposed. `ml/check_sim_transfer.py` had already shown the same thing for the
models — 2.93 m/s speed error on real data against 8–20 m/s on synthetic — so
this is the same finding reaching the estimator.

### Tier R provenance

Converted by `scripts/iovnbd-to-replay.mjs`, which screens hard and reports what
it drops. Of 26 IO-VNBD sequences, **two are emitted**:

| log | duration | GPS | rigid-mount corr |
| --- | --- | --- | --- |
| `iovnbd_S1` | 86.2 min | median 3 m, one fix per ~9.8 s | 0.963 |
| `iovnbd_S3c` | 62.0 min | median 4 m | 0.954 |

Everything else fails one of three screens: the phone was not rigidly mounted
(the gyro does not see the car's yaw — 21 sequences), the recording is too
short, or the data is impossible (`S3b` contains a 20 rad/s angular rate).
Notably **`Vw02` fails at 0.234** despite being the longest sequence, so it is
not usable for anything about turn geometry.

Road graphs for both routes are committed as `road_graph_iovnbd_s1.json` and
`road_graph_iovnbd_s3c.json`.

### Known limitations of Tier R

- **10 Hz**, not the 50–100 Hz a handset delivers. Not upsampled: there is no
  information above 5 Hz in the recording and interpolated samples would be
  invented data the engine would faithfully integrate.
- **GPS updates only every ~9.8 s**, so the withheld ground truth is sparse and
  truth between fixes is interpolated.
- **No barometer and no per-satellite data**, so the altimeter, NavIC reporting
  and Model 4's C/N0 features are untested by these logs.
- **Only the vertical gyro channel is emitted.** IO-VNBD's gyro columns are
  Euler angle rates, not body axes, so no permutation of them is a body-frame
  angular velocity. The vertical rate is measured and verified (a real 90° turn
  integrates to 92.1°); the other two are not knowable from this data and are
  not invented. Consequence: pitch and roll come from the accelerometer anchor
  alone, which is right for a bolted-in phone and would not be for a handheld
  one. See the long comment in the converter.

The eval harness treats both identically — that is the point of having a format
rather than a special case. But `docs/benchmarks.md` states at the top when
every log is simulated, because presenting a simulated figure as a road result
would be the most damaging thing this project could do.

## Recording a real one

Drive or walk a route with **good** GNSS for five to ten minutes with the app
recording, then use **Download recording (.jsonl)** and drop the file here as
`drive_<place>_<n>.jsonl`.

Good GNSS throughout is the requirement, not a nicety: the recorded fixes become
the ground truth that the artificial outage is scored against. A log recorded in
an urban canyon measures the estimator against a bad reference and tells you
nothing.

```bash
pnpm eval -- --list
pnpm eval -- --log drive_jabalpur_01.jsonl --config full
pnpm ablation
```
